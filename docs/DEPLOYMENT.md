# Deploy to Render

Repository: https://github.com/ArlandProperties/main

## Resources in render.yaml

- `arcland-properties`: Node web service, Virginia, Starter plan.
- `arcland-postgres`: private PostgreSQL database, Virginia, Basic 256 MB plan.
- Build: `npm ci --include=dev && npm run build`.
- Start: `npm start`.
- Health check: `/api/health`.
- `DATABASE_URL`: populated from the managed database, never committed.
- `SETUP_TOKEN`: generated by Render, never committed.
- `NODE_ENV=production`, Node 24.22.1.

These plans incur charges. Review Render's plan and current costs before applying. The database denies external IP access; the web service uses its internal connection string. Do not use ephemeral web service disk for production data.

## Initial setup

1. Apply the reviewed Blueprint in your confirmed Render workspace.
2. Wait for the database and web service to be healthy.
3. In the web service's Render **Environment** page, securely view the generated `SETUP_TOKEN`. Do not paste it into chat or commit it.
4. Open the web service URL. Create the first administrator with that token and a strong password.
5. After setup, the first-owner endpoint rejects all additional setup attempts. Rotate/remove the token in Render after setup if desired.
6. Add team members inside **Team & access**. Share initial passwords privately.
7. Optional: load fictional records using **Settings → Load sample portfolio**, before adding real records.

## Operations

- Enable PostgreSQL backups and test recovery according to your Render plan.
- JSON exports are record snapshots, not full database backups.
- Password resets for team members are performed by an administrator in Team & access.
- If the only administrator loses access, perform a controlled database-level password reset with your hosting administrator. There is no unauthenticated password reset endpoint.
- Auto deployment is configured on commits. Failed health checks should prevent a bad release from replacing a healthy deployment; verify this behavior in your Render service settings.
- To roll back code, redeploy a previous successful commit in Render. Back up the database before schema changes. This initial schema uses additive table/index creation at startup.

## Existing application

The old private Sites app is not updated by GitHub or Render. Browser-local sample changes from that app are not automatically imported. The new database starts empty and the new public URL requires sign-in.
